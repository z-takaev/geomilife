# Правила проекта

- Все Markdown-инструкции (`*.md`) всегда писать на русском языке.
- Всегда запускать Artisan команды через Sail: `sail artisan ...`.
- Всегда запускать Composer команды через Sail: `sail composer ...`.
- Всегда запускать npm команды через Sail: `sail npm ...`.
- После изменения кода обязательно запускать форматирование командой `sail composer format`.
- Не использовать Laravel-атрибуты. Конфигурацию классов Laravel задавать традиционными свойствами и методами класса.
- Весь пользовательский текст в Blade-шаблонах, включая значения текстовых HTML-атрибутов, оборачивать в хелпер `__()` для последующей локализации.
- В среде Codex доступ к Docker-сокету может быть запрещён песочницей. В этом случае Sail ошибочно выводит `Docker or Podman is not running`, а `docker info` возвращает `permission denied` для `~/.docker/run/docker.sock`; это не означает, что Docker остановлен.
- Если команда Sail не может обратиться к Docker из-за `permission denied`, повторить необходимую команду с расширенным доступом (`sandbox_permissions: require_escalated`). Не предлагать пользователю запускать Docker и не переходить на локальные PHP, Composer или npm, пока состояние контейнеров не проверено вне песочницы.
- Для безопасной проверки форматирования без изменения файлов использовать `sail composer format:check`; для исправления форматирования после изменения кода использовать `sail composer format`.
- Директория `/template` в корне проекта содержит исходный HTML-шаблон для верстки сайта. Использовать его как основу, переносить нужные элементы в Laravel/Blade/Livewire и адаптировать под требования проекта.
- Директория `/template` не должна попадать в git; она должна быть указана в `.gitignore`.
- Коммиты в git всегда оформлять по Conventional Commits.
- Текст коммита всегда писать коротко, на русском языке, в повелительном наклонении настоящего времени. Примеры: `feat: создать сущность для акций`, `feat: подключить filament`.
</project-rules>

# Слой меню

- Состав, порядок, названия и ссылки меню описывать в `app/Providers/MenuServiceProvider.php`: метод `header()` — меню шапки, `footer()` — колонки футера, `catalog()` — дочерние пункты каталога.
- Использовать существующий `App\Navigation\MenuItem`: `MenuItem::make('Название')->url('...')->children([...])`. Ссылка по умолчанию — `#`; дочерние пункты — массив объектов `MenuItem`.
- Метод `->isCatalog()` устанавливает признак особого оформления каталога. В Blade читать `$item->catalog`; наличие подменю проверять через `$item->hasChildren()`. Не определять оформление по названию или позиции пункта.
- Провайдер передаёт данные через `View::composer`: `$items` в `resources/views/partials/navigation.blade.php`, `$columns` в `resources/views/partials/footer-navigation.blade.php`. Меню собирается при отрисовке соответствующего представления.
- Blade отвечает за разметку и оформление, а не за состав меню. Названия выводить через `__($item->label)`. Сохранять обычные ссылки, два уровня выпадающего списка внутри верхнего пункта и выделение каталога.
- В меню футера верхний `MenuItem` описывает заголовок колонки, его `children` — ссылки. Partial `partials.footer-navigation` подключается из `resources/views/partials/footer.blade.php`; сохранять классы мобильного раскрытия колонок.
- Каталог пока содержит статические примеры. Будущую загрузку категорий и подкатегорий из БД подключать через `catalog()`, сохраняя формат `MenuItem` и исключая отдельный запрос на каждую категорию. Не выполнять запросы непосредственно при загрузке провайдера.
- Сохранять слой простым: использовать `MenuItem` и `MenuServiceProvider`, не добавлять enum, отдельные классы пунктов или менеджеры меню без необходимости.
</navigation>
